# Megagame

A web app for running a megagame: a long-running, many-team strategy and roleplay game.
Players submit structured orders. The app pre-rolls, pre-calculates and simulates as much as possible, and the DM reviews and publishes the results.

The app is theme-neutral. "Utterdark" is one preset ruleset.

In the app, **/help/player** and **/help/dm** are short guides for players and the DM.

**First time?** Follow **[docs/SETUP.md](docs/SETUP.md)**. It walks through putting the app online with free Supabase and Vercel accounts, on Windows, step by step.

## Tech

- **Next.js 16** (App Router) + **TypeScript** + **Tailwind CSS 4**, hosted on **Vercel**
- **Postgres on Supabase**, accessed only from the server through **Drizzle ORM**
- **Vitest** for tests
- **jose** for signed session cookies

## Project layout

```
src/
  engine/      Pure game-rules code: dice, seeded RNG, the ruleset format,
               stat blocks, effects, derived stats, SRD converter,
               fog of war (world/), order checks, movement and economy (orders/),
               round resolution: proposals, roll tables, queue, end of round (resolve/),
               the combat simulation and area effects (combat/).
               No database or web code in here, so it can be tested on its own.
  presets/     Blank and Utterdark starting rulesets
  data/        Bundled SRD 5.2 monsters (generated by scripts/build-srd.ts)
  components/  UI: the design tokens and team colours (theme/), icons and team emblems (icons/),
               the map-first screen: toolbar, dock, movable windows, side panel, popups (shell/),
               the ruleset editor, the map (MapCanvas, MapEditor, WorldMap),
               the player screens and order builder (play/)
  db/          Database schema (schema.ts) and connection (index.ts)
  lib/         Server helpers: sessions, join codes, a team's fogged view, the fogged map image,
               resolving rounds with undo (resolution.ts), published results
  app/         Pages and server actions
    page.tsx       Landing page: join a team
    dm/            DM login, games; per game, (shell)/ holds the World map with Teams, Resolve and
                   Diplomacy as windows over it; map editor, ruleset, history and settings are full pages
    api/assets     Serves uploaded images (DM only)
    api/play/map   The map image with the team's fog of war painted on
    play/          Player screens: the team's map fills the screen (layout.tsx); overview, orders, results,
                   units, regions, inventory, trades, rules and help open as windows over it
    help/          The player guide and DM guide
    api/health     JSON setup check
drizzle/       SQL migrations (generated from schema.ts, applied on every deploy)
scripts/       migrate.ts, the Utterdark sheet importer, the load-test game
docs/          Setup guide, data model, fog of war, resolving a round, Utterdark preset notes, proposals
```

## Commands

| Command | What it does |
|---|---|
| `npm run dev` | Run locally at http://localhost:3000 (needs `.env.local`; see `.env.example`) |
| `npm test` | Run the unit tests |
| `npm run typecheck` / `npm run lint` | Check types and code style |
| `npm run db:generate` | After editing `src/db/schema.ts`: write a new SQL migration into `drizzle/` |
| `npm run db:migrate` | Apply migrations to the database in `DATABASE_URL` (Vercel does this on each production deploy) |
| `npm run seed:load-test` | Add a 15-team, 160-region test game to the database in `DATABASE_URL` (see [docs/PERFORMANCE.md](docs/PERFORMANCE.md)) |

## Security model

- The browser never talks to the database. There is no public Supabase key in the app. Every read and write goes through server code that checks the session first.
- Row-level security is switched on for every table with no policies, so Supabase's auto-generated public API can't read anything even if someone finds the project URL. A test (`src/db/rls.test.ts`) fails if a new table forgets this.
- Players join by exchanging a team join code for a signed, httpOnly session cookie. Each request re-checks the session against the database, so regenerating a team's code signs that team out immediately.
- The DM logs in with the `DM_PASSWORD` environment variable.
- All player data comes from the server after it has computed **that team's** fog-of-war view (see [docs/VISIBILITY.md](docs/VISIBILITY.md)). Unseen regions, hidden units, the monster library, roll-table outcomes and unlearned recipes are never sent to a player's browser. The map image is fogged on the server too.
